# Q: Я не требую от тебя что то больше дорабатывать в проекте, хочу понять как он работает в целом, авторизацию я разобрал, давай пройдемся по эндпоинтам для изучения. Чтобы я как разработчик 1С разобрался в этом проекте

## Answer

Expanded from original query via graph vocab: [study, session, card, mode, answer, evaluate, review, srs, due, choice, type, describe]. Учебная сессия не хранится в БД: GET /api/v1/study/session вычисляет карточки из Word по due_filter, назначает mode по srs_level и возвращает StudySession DTO. PATCH /words/{id}/answer и POST /words/{id}/describe обновляют SRS через _apply_srs и атомарно добавляют ReviewLog. Describe оценивается текстовой моделью по скрытому scene_prompt с офлайн fallback. Важные нюансы: обычный answer доверяет correct от клиента, а type и choice через этот HTTP-маршрут журналируются как choice.
