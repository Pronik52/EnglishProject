# Q: Я не требую от тебя больше ничего исправлять, давай изучим мой проект со стороны бэкенд. Начнем с авторизации, почему именно так реализовано и как работает, что бы ты улучшил. Покажи прям куски кода в файлах как выполняется эндпоинт

## Answer

Expanded from original query via graph vocab: [auth, authenticate, authentication, current, decode, email, login, password, register, token, user, verify]. Поток: app.main монтирует auth router под /api/v1/auth; register валидирует UserCreate, проверяет email, bcrypt-хеширует пароль и сохраняет User; login принимает OAuth2 form, вызывает authenticate_user и создает JWT с sub=email и exp; OAuth2PasswordBearer извлекает Bearer token, get_current_user декодирует его и повторно загружает User из БД; защищенные word endpoints передают current_user.id в owner-scoped CRUD. Сильные стороны: слои, DI, response_model без хеша, generic login error, повторная проверка пользователя. Приоритеты улучшения: сохранить WWW-Authenticate в global handler, исправить OpenAPI tokenUrl на canonical endpoint, отказаться от localStorage в пользу HttpOnly cookie/BFF для browser, ограничить CORS origins, rate-limit login, validate settings, use stable user id and required JWT claims, handle duplicate registration race, normalize email, consider Argon2id, add negative token tests.
